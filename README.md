# apollo-pack

A public pack of local-first [Agent Skills](https://skills.sh) and host
plugins. Every skill is a set of standard-library Python scripts that print one
JSON envelope per run; the plugin is a small nanobot extension. None of them
installs, mutates, or talks to a scheduler on its own.

## Catalog

The table below is generated from each item's own metadata — `SKILL.md`
frontmatter for skills, `pyproject.toml` for plugins — and mirrored in
`catalog.json`. After editing an item, refresh both:

```bash
uv run tools/catalog.py build
uv run tools/catalog.py check
```

## Install

### Skills

Copy the skill folder into your host's skills directory so that
`<skill-id>/SKILL.md` is discoverable. The folder name must stay the same as
the skill id.

```bash
cp -R skills/habit-tracker /path/to/your-host/skills/
```

Each skill's README covers its own requirements, storage location, and
quick-start commands. All four skills share a uniform scheduler interface
(`schedule-hint`), documented in [docs/scheduling.md](docs/scheduling.md).

### Plugin

`plugins/nanobot-live-status` is a nanobot tool plugin. It must be installed
into nanobot's own tool environment, not your project venv:

```bash
uv pip install --python "$(uv tool dir)/nanobot-ai/bin/python" ./plugins/nanobot-live-status
```

See `plugins/nanobot-live-status/README.md` for configuration and removal.

## Repository layout

```
apollo-pack/
├── README.md
├── VERSION                 # pack semver
├── catalog.json            # generated by tools/catalog.py
├── docs/scheduling.md      # the shared scheduler-latch contract
├── skills/<id>/            # one Agent Skill per folder
├── plugins/<id>/           # one host plugin per folder
└── tools/catalog.py        # catalog generator + validator
```

## Secrets

`kilo.json` is a local, gitignored configuration file and must never be
committed. `kilo.example.json` is the redacted template to copy from.
